# 视频作品长期归档

[作品页](https://yjr927.github.io/idore_tools/gallery.html) 读取 `site/data/creations.json`。成片与封面保存在 `site/generated/<id>.mp4` 和同名 JPG，不依赖短期 Actions artifact 的下载地址。它们没有自动到期时间，但仍受仓库、网站可用性与容量限制；单片超过 90 MiB 时停止归档，不截断或静默压缩。

## 当前生产队列

Work 每天纽约时间上午 9 点最多收录 4 条原片：K-pop 最多 2 条、虚拟偶像最多 2 条。GitHub 云端匹配同分组、同人数角色，按“原片动作提取 → 新白模渲染 → Seedance 角色视频”制作。当前支持单人，多人及缺少角色的任务等待。

生产队列在视频完成后立即保存成片、封面与作品索引，再处理英文文案和标签。文案现经 OpenRouter 调用 OpenAI 模型，与视频共用 GitHub Secret `OPENROUTER_API_KEY`；默认模型为 `openai/gpt-5.4-mini`，由 Variable `OPENROUTER_TEXT_MODEL` 设置。直接 OpenAI 密钥仅用于可选变装造型图。

任何文案失败都不应丢弃已完成视频。KAI 已有成片的文案已在 [OpenRouter 云端验证](https://github.com/yjr927/idore_tools/actions/runs/44215375401)中成功，模型为 `openai/gpt-5.4-mini`，目前为待审核（`pending_review`）。已保存 3 条英文候选、5 个相关标签与 5 条真实检索来源；没有标签被验证为当前趋势，不能把来源列表称为实时热榜。此前直接 OpenAI 的 `insufficient_quota` 保留在历史工作流回执中，不再代表 KAI 当前状态。视频与文案状态分别显示，审核、退回或 TikTok 上传状态不改变“该视频是否已生成”的事实。

生产队列的白模另以 `clay-<TikTokID>.mp4` 保存，供审核对照；它不是最终角色成片，不加入作品索引。原片、动作关节点文件、临时签名媒体地址、提示词、密钥和 TikTok 私有上传回执不归档到作品页。

## 原有手动云端任务

`Archive completed video creations` 继续监听视频生成及完整造型视频工作流。仅接受本仓库 `main` 上人工触发的已结束任务，并重新读取 GitHub 元数据核对；整体任务失败或取消时也会检查，因为文案失败之前可能已有已完成视频。

此独立归档只认安全摘要中 `completed` 的视频及精确匹配的 `video-<32hex>.mp4`，不导入原片、白模预览、造型图片或私有任务状态。归档不调用付费视频、图片或文案 API。非 main、fork、非约定工作流、ZIP 穿越／链接、超限文件及不完整摘要会被拒绝；GitHub API 凭证不转发给 artifact 存储地址。

## 去重与记录

归档检查视频格式、时长及尺寸并生成封面。稳定 ID 为 `video-` 加成片 SHA-256 的前 24 位，按**完整 SHA-256** 去重；相同文件只保留一条。保留已有人工分类与角色资料；缺少资料时记“未标注角色／unknown”，不猜测男女或人数。作品索引仅保存约定的公开元数据、相对媒体路径、生成记录链接和 SHA-256。

原有两条旧视频已回填：KAI 白模手势跟拍和“小鹿 · 接口测试”。接口测试是测试样片，不冒充当前每日采集生成的新作品。作品按已知完成时间倒序显示。

并发写入冲突时重新读取 main、重新合并并有限重试，不强制覆盖。归档失败可重跑归档任务，不重跑付费生成。完成后部署最新 main 的整个网站。

## 访问与限制

当前网页的制作、审核、设置分别位于 `create.html`、`review.html`、`settings.html`；模型密钥只在 GitHub Secrets 中使用。当前入口不再依赖浏览器 OAuth 或浏览器直连生成。历史浏览器直接生成的文件不会因此自动补回；过期／遗失 artifact、未下载成功的远端结果也需另行处理。

公开作品页和仓库可访问成片；这不是私有媒体存储。TikTok 尚未完成应用与账号接入，审核通过不等于已发送草稿；即使接入后，官方视频草稿 API 也不能附带文案标签，仍需进入 TikTok 粘贴、编辑及最终发布。
